# v1.5.29 implementation / QA handoff — 2026-10-28

Branch: `feature/lan-local-beta`. Issue #7 P0 and the final Wi-Fi-only crossplay
decision are implemented in source; release acceptance still needs the checks below.
Do not claim Internet room-code hosting: that prototype was removed.

## Changes

- Shared Royale zone 1650 → 1200 → 900 at 4/8/12 minutes. Host applies 1% max-HP
  damage per second after ten seconds outside. Pause / special arenas remain exempt.
  Egg Rush uses a fixed 1600 soft boundary and retains its own score/respawn rules.
- Royale support nests: first five at 30 seconds, up to two per 45 seconds,
  untaken cap six, TTL 180 seconds, fair allocation by missing support slots,
  safe terrain and all-camera spawn rejection. Max two pets per trainer unchanged.
- Royale opening multiplier 2.3 → 1 over 180 seconds; opening allocations at most
  two per trainer over 3–12 seconds; burst respects the existing 60→80 enemy cap.
- AI goals respect the zone. A* expansion counts, enemy/pet/nest counts, world
  caches, frame cost/FPS/dropped frames and output byte rates are instrumented.
- Bots no longer cause allocation of full outgoing client frames that would be
  immediately discarded; unused bot event queues are drained. Human frames remain.
- Ranking bounds keep the egg guide beside the Royale sidebar rather than on top.
- `WIFI_CROSSPLAY.md` describes local WebRTC pairing on any supported device,
  without Internet signaling, STUN/TURN or rented hosting. Original LAN invitations
  and standalone AI remain supported. Menu pairing uses two-way QR/text/file exchange.

## Performance and release gates

The initial PC ten-minute load run (before the bot-frame optimization) was poor:
about 9.6 FPS with 10 participants, ~8.8 ms mean measured frame body, ~30 ms p95,
and game time advanced much slower than wall time. This is not a passing 50–60 FPS
result. Updated measurements include the whole UI tick and byte rates. CI runs
30-second 2/4-trainer comparisons plus a ten-minute ten-trainer keepalive fixture
for each packaged platform; it must retain all existing assertions and report
actual numbers. The fixture heals trainers for sustained load and does not prove
natural AI survival balance. Saved baseline output is under local `dist/qa/`.

Do not mark physical Android Host >=30 FPS, mixed-device same-Wi-Fi connectivity,
router compatibility or offline Web asset availability verified without real devices.
No 20-player support, seamless Host migration or in-match reconnect is promised.
Build PC/Web/Android from the same published commit and inspect the three workflow
results. Only a persistent-key `SIGNED-UPDATE` APK may be delivered as a player
update; `DEBUG-TEST-ONLY` is never a substitute. Save keys and personal ticket/Shiny
ownership are unchanged. See `ANDROID_UPDATE_SIGNING.md`.
